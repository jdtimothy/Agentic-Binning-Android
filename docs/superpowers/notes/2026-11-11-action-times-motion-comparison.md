# Motion-timed actions: implementation and comparison

Branch: `feat/action-times-by-motion`, based on `7b065f4` (Step 1 evidence).
Main remains unchanged at `bcb9b61`. Owner approved Step 2 after the phone check.

## Behavior

- Main analysis still sees every sampled frame across the whole video, using
  the unchanged sampling and interleaved timestamp layout. Only action generation
  moves out of this call. Both photo and video grammar fix `"actions": []` as
  literal text (no whitespace choice before the empty array).
- Prompt version is `analysis-v3`. No schema migration or existing-analysis rewrite.
- Prepared video JPEGs are downscaled to 32x32. Mean absolute RGB difference
  excludes pixels black in both frames (each channel below 16).
- Peak below 8 means no moment calls. Otherwise opening plus up to four equal
  intervals' greatest changes are selected, each at least 8 and 40% of peak.
- Each selected frame gets a fresh single-image call on the already-loaded NPU
  model: 40-token cap, at most 14 words requested, capital-to-full-stop grammar,
  no previous frame or full-description context. Phrases longer than 14 words
  are rejected. A length stop retries once, then that moment is skipped.
- The app supplies nearest-second `m:ss` from the frame's sample position.
  Duplicates sharing at least half of the larger unique long-word set are
  dropped (Windows heuristic); zero/one distinct phrase yields no actions.
- Assembled actions are saved in both structured result and raw JSON. Stored
  profile remains the main-call profile, not a misleading sum against its cap.
  Per-moment profiles and whole-item elapsed time are logged separately.
- Cancellation/native user stop does not save a partial item; moment model
  failure stops the run, matching existing main-call error handling.

## Measured quality: do not treat implementation as a proven accuracy win

These are the same three coastal-wave clips used in Step 1. The new code is
working, but **the small comparison does not show reliable late-event detection**.
Repeated single-frame wave descriptions are often removed as duplicates, and
localized spray can score just below the threshold. Do not merge on a claim
that the late-wave issue is solved.

| Clip | Main / Step 1 action times | New run 1 | New final run |
| --- | --- | --- | --- |
| `20260919_120531.mp4` (35.003 s) | 0:00, 0:05, 0:10, 0:15 | none | none |
| `20260919_121906.mp4` (36.705 s) | 0:00, 0:10, 0:20, 0:30 | none | 0:00, 0:16 |
| `20260920_174506.mp4` (47.362 s) | 0:00, 0:05, 0:10, 0:15 | 0:00, 0:18 | none |

Final run phrases for the second clip:

- 0:00 — Waves crash against black rocks
- 0:16 — Waves crashing against rocky shore

This also exposes the lexical deduplication's limits: similar meanings can
survive when the words differ. Repeated calls varied despite the low-temperature
sampler; these are observed runs, not deterministic golden outputs.

Run 1 selected sample positions (ms):

- First clip: 0, 4375, 8750, 21876, 30627. All five descriptions reduced to
  variants of waves crashing against rocks; deduplication suppressed the list.
- Second: 0, 2294, 16058, 20646, 34410. All five descriptions were similar.
- Third: 0, 8880, 17760. The late plume frame at 41441 ms scored
  7.9282407407407405, below the fixed threshold of 8, so it was not selected.

Thresholds and heuristic deliberately match the brief/Windows reference rather
than being tuned to this small test. The owner should compare varied clips
(person leaving, a pan to a new subject, still scenes), not only repetitive surf.
